# Folder workspace and documents

Implementation: 2026-11-07. See [verification](verification-2026-11-07-documents.md) for installation and acceptance status.

Frame previews Markdown, HTML, JPEG/PNG and MP4/MOV/M4V in either local or RelayBar folders. The native file tree shows real folders and files; expansion reads one directory of metadata. New roots start in Preview, with a large viewer and resizable/collapsible sidebar. Clicking a folder switches to Grid and retains the folder selection, without changing the saved root layout. Existing local folders migrate to Grid; subsequent layout choices persist by root. Info is optional, initially closed for documents, with a separate remembered media preference. Grid retains thumbnail sizing, selection and attached preview.

Markdown is rendered by the shared `MarkdownRendering` library, the same renderer and reading design RelayBar uses (see the [Markdown preview spec](../../../../docs/system-specs/modules/markdown-preview.md)); Frame supplies its own palette. It covers GitHub-flavoured tables, task lists, strikethrough and autolinks; Obsidian frontmatter, callouts, comments, highlights, footnotes, wiki links and tags; code blocks with a language label, highlighting and Copy; and typeset math. Raw HTML in Markdown is shown as literal text and never runs. Wiki links, tags and footnote references are shown but do nothing when clicked. Copy works only on a Markdown page, from a real click on a link carrying that renderer's token, and reads the block in an isolated script world. A document above 2 MiB is rendered as plain GitHub-flavoured Markdown: no Obsidian pass, highlighting or math, and raw HTML is left out. Local images and links resolve from the document directory. The app bundle carries the highlighter's and the math font's resource bundles, pruned to what is used, with their licences. This source has not replaced the installed build, which uses swift-cmark directly and omits raw HTML. HTML retains its own styles, inline/local JavaScript, controls, canvas and fetch of local data. Text, JSON and common source/data extensions use an escaped plain-text preview; binary and oversized files offer Open in Default App. No editor, development server or new remote-host dependency is added.

One reusable WKWebView renders documents, with a nonpersistent website data store. Frame's Back/Forward retain document scroll; WebKit's implicit Backspace history navigation is disabled so it cannot bypass file selection. Switching Preview/Grid keeps the renderer. A serial background parser prevents simultaneous large Markdown parses. Document keyboard focus owns Delete, F, arrows and Escape; those keys continue working in the media viewer. File-tree arrows use native outline behavior, and Delete acts only on a selected primary file. The sidebar starts at 260 points, retains resizing and gives window growth to the preview.

Current Task 058 source routes media and document previews through owned format registrations. Settings exposes preview toggles and lower document byte limits, persisted in the versioned feature tree separately from favorites/bookmarks and remote grants. Disabling a format closes its active previews and drains their work; enabling it again refreshes visible previews. Video playback has an independent registration from its poster, so losing thumbnail/helper support leaves a playing video intact. Remote video metadata uses file access; helper image metadata is an optional integration. Document links go through app selection so the target format's settings apply. These local changes have not replaced the installed build. See the shared [composition contract](../../../../docs/system-specs/shared/composition.md).

The current source also migrates media Info, remote visibility, local Subfolders, thumbnail width and per-root layouts into that tree once. Original UserDefaults values remain recoverable. Legacy Grid defaults are assigned when the catalog becomes available, preserving explicit layouts and all catalog roots. Settings effects follow successful persistence; a failed remote-hide save leaves the current session usable. Navigation remembers its captured root asynchronously and drains accepted writes on quit. Native pane/window autosave and domain data remain separate.

## Folder browsing and filters

Both local and RelayBar listings populate the main workspace from all regular, non-hidden, non-symlink files. Supported primary assets retain their grouped companions. The file-type menu (All files, Images, Videos, Documents, Other files) combines with favorite status and applies in both layouts. Documents includes Markdown, HTML and recognized text/code/data extensions; Other files contains unsupported formats. Filters persist across folder navigation in the open root and reset on a fresh root open. Explicitly choosing a file in the sidebar clears only filters that would hide that file. Archive remains separate.

Filtered counts show N of M files. An empty result offers Show all files; an empty direct folder with children explains subfolder navigation. Directory loading and failures show Reading folder or Folder unavailable with Retry. Remote recursive limits count every file, including general files and companion rows. The text descriptor and scanner share one extension list; migration preserves the previous enabled state and byte limit.

## Resources and changes

- A random-host `frame-document:` scheme serves only regular files below the opened root. Local reads use root-relative no-follow descriptors; remote reads use RelayBar's existing authorized listings and fingerprint-checked transfers. Siblings and nested relative paths work. Traversal and symlink escapes are rejected.
- Online scripts, stylesheets, fonts, images, media and fetch/WebSocket requests are allowed, following the user’s 2026-11-07 approval. macOS App Transport Security remains unchanged, so insecure HTTP may be rejected. Early/header content policies still restrict file URLs, frames, objects and form submission. Scripts have no native mutation/SSH bridge. A user-clicked web link opens the default browser. Unavailable folder resources leave a concise indicator over the remaining page.
- Limits: 10 MiB per document, 32 MiB per resource, 64 MiB of document bytes, 128 resource paths per page, 256 document history entries. Directory metadata is bounded to 64 listings / 20,000 files. One active renderer; no document thumbnails are rendered in the background.
- Remote opening fetches only the document and requested dependencies. A three-second foreground-only poll batches stat checks for loaded resources through the bridge's `documentStat` request; changed bytes are refetched. A disconnect retains the last good page and exposes Retry. Frame never writes RelayBar history.
- Local FSEvents coalesce updates and reload affected cached directory branches. Atomic replacements retain selection. Removal keeps the missing selected file in place. Dropped/root-change events reconcile loaded branches. Refresh is available; for documents it refreshes the visible directory without resetting the preview.
- Document bytes remain in bounded memory/temporary remote storage. Existing favorites/bookmarks remain in the catalog; no persistent document library/cache is introduced. HTML application state may reset on reload.

## File actions

Markdown and HTML are primary items. `result.png`, `result.md` and `result.html` are independent. Existing media owners still group non-primary files such as `.prompt.json` and `.qqq.txt`; supported documents cannot become their companions. Companion files also appear at their real paths in the tree and All files grid, with a Companion label. Their direct preview has no separate delete, archive or export action; selecting the owner manages the group. General non-primary files are previewable, favoritable and exportable, but do not gain destructive actions.

A document's linked images, scripts, stylesheets and data are dependencies, not owned companions. Delete/Archive/Export affects that document alone. Local Trash/Undo and permanent remote Delete without confirmation are unchanged. Archive remains separate. A copied HTML file is not a packaged website; its relative dependencies need their existing layout. Archived documents can be previewed as stored, but references to assets left outside the archive record may be unavailable.
