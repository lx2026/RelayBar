# Frame viewer handoff and remote assets

Bridge v7 bundles from commit `a896188` plus approved version/build metadata changes were installed as RelayBar 2.0.0/22 and Frame 2.0.0/17 on 2026-11-16. Both are universal, Developer ID signed, notarized and stapled; installed Gatekeeper checks and launch passed. Frame uses `com.lx2026.Frame`; its initial bundle ID change started fresh settings/library state while retaining the previous sandbox data, and the subsequent 2.0.0 installation preserves the new container. Public stable remains 1.6.0/11, and native interaction and live-host acceptance remain open. See [2.0.0 installation evidence](../../verification/066-local-notarized-install.md#200-follow-up). The earlier bridge v6 installation on 2026-11-07 had native local document/media and saved-folder document checks; those checks do not certify the newer source. No public release was published.

Open in Frame hands off the current folder/selection through a one-use 60-second nonce. It is a RelayBar plugin, on by default only when Frame was installed as RelayBar launched; an explicit choice in the Plugins window always wins. While it is off RelayBar shows nothing of Frame (no Open in Frame buttons, no Frame Viewer access row in Settings) and its bridge does not listen. Turned on by hand without Frame, the button shows a message that Frame isn't installed; an incompatible Frame shows an update message. No download website has been supplied. RelayBar owns SSH credentials, aliases, arguments and host-key checks. Frame receives opaque IDs, paths and bounded content.

Frame reads but **never changes RelayBar history**, including explicit descendant opens. Legacy rememberOpen is a compatibility no-op. RelayBar's own history behavior is unchanged.

## Session and wire

Source and the current installed test pair use wire v7. Older wire versions are rejected as incompatible, so both apps must be updated together.

- **One connection per session.** Frame opens one connection to RelayBar's socket when it connects and sends every request on it. Each request carries an id and its reply carries the same id, so a slow request never delays another.
- **Identity once per connection.** Each peer verifies the other's audit-token code identity when the connection opens. The check itself is unchanged.
- **The end of the connection is the end of the session.** RelayBar quitting, stopping its host or crashing ends the connection, and Frame withdraws its remote features at once without sending anything. Frame quitting or crashing ends it from the other side, and RelayBar cancels that session's jobs and removes their transfer directories immediately; jobs no longer wait for an expiry timer.
- **Revoke.** RelayBar sends connected sessions a notice carrying the reason and then ends those connections. New connections are still accepted and are answered as unauthorized.
- **Long operations.** A request that starts work still returns a job id. Frame's status request for that job is held and answered when the job finishes, or after at most half a second with transfer progress. Frame no longer polls on a timer, and makes no periodic liveness request while connected.
- **Cancellation.** A cancelled caller stops waiting. If RelayBar had already accepted work for that call, the late receipt is released automatically.
- **Other versions.** A v6 peer's bare request is answered in the v6 shape as incompatible and never reaches the broker. A v7 Frame treats a v6 reply as incompatible. Failures end a session only when RelayBar names them (unavailable, unauthorized, incompatible); a file or helper error leaves it usable. The former matching of English error strings is removed.
- Frame still looks for RelayBar every three seconds while it has no session; that is discovery, not liveness.

## Permissions and interface

Both peers verify kernel audit-token code identity against expected bundle IDs and Apple-anchored Developer ID team 39HYFR5Z65. The shared App Group socket is mode 0600; Frame remains sandboxed. RelayBar protects each accepted connection against SIGPIPE before anything can write to it; a peer that has already hung up by then is closed unanswered.

Linked Frame access permits browsing, previews, original downloads, Archive/Restore and direct Delete. There is no second write prompt or delete confirmation. Revoke retires access and jobs/services. There is no trash, upload or arbitrary-shell endpoint. Older protocol versions are rejected.

## Prompt Search

Prompt Search is a plugin, on by default. While it is on, the library column has a search field (placeholder "Search") under its top row, in both modes; Command-F focuses it, first leaving the full-screen viewer and showing a hidden library column, and Escape clears it. Typing filters the current folder, after its other filters, to the assets whose text contains every word typed, ignoring case and diacritics. Words are separated by spaces; quotes are ordinary characters.

- An asset's text is its file name and its companion text. On this Mac that is the whole of each companion file up to 2 MiB, and a PNG's text chunks, to 256,000 characters per asset. Through RelayBar it is the companion text the session returns, which is the first 24,000 characters of each companion; embedded PNG text is not searched remotely. The sentences shown in place of an unreadable, oversized or binary companion are never searched.
- A search starts 200 ms after the last change to the query or to the folder scope. A newer search cancels and supersedes an older one; the list keeps showing the previous result until the new one arrives. The field shows "N of M" at its trailing edge while a search narrows the list.
- The selection always stays inside the filtered list, and delete, archive, restore and favourite read their targets from what the list shows, so they never apply to an asset the search hides. Choosing a file in the sidebar or through a link ends a search that hides it, and Show all files ends the search along with the other filters. Undo is the exception: it restores what the last Trash operation moved whether or not the search shows it.
- Text is read at most six assets at a time, under the folder access or session the realm already holds, and kept in memory while the plugin is loaded, up to 16,000,000 characters; passing that empties the cache. Each asset is matched as it is read, so a search holds no more text than the cache does. An asset is read again when its size, modification time or file identity changes, or a companion's does, or a companion is added, removed or renamed; an asset with a companion or PNG that could not be read, or whose read was cancelled, is not cached. A search in progress is joined before the plugin finishes unloading. Nothing is written.
- Single keys act on the selection whenever no text control has focus (Backspace deletes, permanently for a remote file), so typing must never fall through to them. Three things ensure that. The field sits above the tree, which is not rebuilt while someone types. The grid and the viewer, which take the keyboard when they appear, do not take it from a text control being edited. And the key monitor remembers that someone was working in a text control: if that control loses the focus without a click in the window or a key that leaves it (Tab; or Return, Enter or Escape in a field other than search), a key that would run a shortcut is dropped instead, and the search field is given the focus back. Editing commands such as Command-A and Command-V keep that protection on, and Command-Backspace is covered like Backspace.
- When the plugin is switched off, or the session behind a remote folder is withdrawn, the query is cleared, the filter is removed, a pending search is dropped and the field goes away.

## Window layout

The main window is two full-height columns with one hairline between them and no bar across the window ([Task 068](../../task-specs/068-frame-reader-layout.md)). Sizes follow the approved mock. Colours come from the shared house palette ([House style](../shared/house-style.md)) through `FrameColors` and `FramePalette`, which pass through to it; with Paper Appearance on they are the values Frame drew with before the palette moved, and with it off the standard macOS colours. The Markdown page's background is the reader column's paper in either form.

- **Window.** The library column is on the panel colour, the reader column on the paper colour. Content runs under the hidden title bar; the window controls are placed in the middle of the library column's 52-point top row, 16 points in, and are put back there whenever AppKit lays the title bar out again or rebuilds it (resize, key changes, screen changes, leaving full screen). The title bar that holds them is kept no wider than the controls, so no title-bar view lies over the top row's own controls. Empty parts of either top row move the window and a double click there does what the title bar's would. The divider is a one-point line with a nine-point handle; the library column defaults to 260 points, stays between 200 and 420, and keeps its width under the existing autosave name. When the column is hidden, the reader's top row leaves room for the window controls and carries the show-folders button and the mode switch; in full screen and the full-screen viewer it does not. The full-screen viewer lasts only while its window is full screen: it ends when the window leaves full screen by any means (the green button included), closes, or has not entered full screen within three seconds.
- **Library column.** Top row: the Files/Icons switch (Files shows one file, Icons the folder as thumbnails; the labels drop to icons before the switch would truncate) and the hide-folders button. Then the search field, the tree and a 40-point footer. The tree is the existing outline of folders and files with 26-point rows, 16 points of indent, kind icons, middle truncation, an accent-filled selected row with white text whether or not it has the focus, and a filled heart at the trailing edge of favourites. The root row is semibold and carries a pull-down with Open…, Parent Folder (remote libraries) and Refresh, beside the scanning spinner; the main menu keeps answering Command-O, Command-Up Arrow and Command-R. In Files mode the tree marks the file on show, in Icons mode the folder. Choosing a file shows it in Files mode; choosing a folder makes it the folder on show and keeps the mode (a remote folder no longer forces Icons). The footer has the kind filter (All kinds, Images, Videos, Documents, Other files; Hide Favorites; Show Sidecar Files; Clear Filters), a favourites-only heart and Archive, which is shown selected while active and leaves Archive when chosen again.
- **Files mode.** One 52-point top row: the name, a kind chip (PNG, MD, HTML, MP4…), for Markdown and HTML a Rendered/Source switch, a spinner while a document loads, then Previous, the position ("6 of 11"), Next, Favorite, Archive (Restore in Archive), Move to Trash (Delete for a remote library) and More: Export Exact Copy…, Original (remote images), Full Screen, Open in Default App, Back and Forward through the documents shown, and Hide/Show Details. In Select mode the row also has Done, the current file's selection toggle and "N selected", because the actions then reach every checked file. Markdown, HTML, JSON and text use the existing document view: Markdown and text read in the shared reading column on the paper, and an HTML page fills the column as a white card with rounded top corners. An image is fitted below a 16-point gap and centred together with the details rail; a video uses the existing player at the video's shape. The rail is 240 points wide with no background: Generation with its copy button, Prompt and Negative blocks and the value pairs (JSON and embedded generation keep separate sections), Capture or Video values, one Sidecar row per companion that opens it, then a muted line with the kind and pixel size and when the file changed, and collapsed File details and All metadata. HTML and text documents show the rail only after Show Details; a Markdown file's details are its outline (below). The empty, loading, connecting, unavailable and error states keep their copy and appear in the reader column.
- **Icons mode.** Top row: the folder's name, "N items" ("N of M items" while filters or search narrow it), kind chips (All, Documents, Images, Video, with counts; the same filter as the footer, a chip with no files is hidden unless chosen), Subfolders with its scanning and incomplete-scan controls, Select/Done and the size slider; chips and then the count give way when the column is narrow. While anything is selected the row ends with "N selected" (as the old bar showed it) and the same Favorite, Archive, Move to Trash and More cluster, acting on the selection. The grid is the existing collection view: 28-point side insets, 16-point column and 18-point row gaps, tiles with a landscape well about three quarters of their width and the name below. Subfolders come first as folder tiles while Subfolders is off and nothing narrows the list; they take the keyboard focus but never join the selection, and double-click or Return opens them. Images and video posters are fitted inside the well, video has a duration chip, documents are drawn as a small page with a kind chip, files with companions carry a `{ }` chip, favourites a heart after the name, a selected tile an accent ring and the file on show an accent pill behind its name. Double-click or Return on a file opens it in Files mode. Entering Icons mode with Subfolders on scans the whole local folder again whatever kind of file is selected.
- **Rendered and Source.** Source shows a Markdown or HTML file's own text through the same plain-text path as any text file, monospaced and wrapped, on the paper rather than in the card. The choice belongs to the document renderer, starts as Rendered and holds while the app runs.
- **On this page.** Beside a Markdown file read rendered, a 200-point rail with no background lists the document's second- and third-level headings (third level indented); the section being read has the accent line and semibold text, and under the list are the file's path within the library and its modified time. The section being read is the last heading whose top has passed a quarter of the way down the view, the last visible heading at the end of the page, or the heading just chosen until the reader scrolls again; choosing a heading scrolls it to the top. The rail is hidden with fewer than two such headings, while the column is narrower than the 680-point article, its margins and the rail, and after Hide Details (which applies to Markdown; it starts shown). The headings are read by Frame's own script in WebKit's isolated client world, which posts to a message handler registered only in that world; the renderer accepts the message only for the rendered Markdown page on show and keeps at most 300 headings of 300 characters. The page world, its script and content policies and its existing script and handler are unchanged.
- **Changed since last opened.** A 6-point accent dot at the trailing edge of a tree row and after the name on a tile (accessibility label "Changed since last opened") marks a file modified since it was last opened in Frame. Only file times are compared, never the Mac's clock, so a remote host's clock cannot hide or invent markers. The first time a build with this feature lists a folder, the newest modification time among its files becomes that folder's baseline (an empty folder's is the distant past); files at or before it are never marked. A file counts as opened only when it is the file displayed in Files mode, including when it changes while displayed; the modification time it had then is recorded, and a later modification brings the marker back. Folders and archived files carry none. Baselines (`FolderBaselineRecord`, keyed `rootID:folderPath`) and opened times (`OpenedFileRecord`, keyed `rootID:relativePath` like `FavoriteRecord`) are SwiftData models in the same catalog as the favourites; a catalog without them has no markers. An opened time is dropped only when a fresh listing of the file's own folder lacks it; files Frame moves to the Trash or the Archive keep theirs, so Undo and Restore bring them back unmarked, and the whole-library scan, which skips package contents the tree shows, drops nothing. Remote libraries take modification times from the listing's ISO 8601 `modified` field, and folders the tree lists as they are expanded get their baselines from that listing.
- **Sidecars.** A companion file (for example `image.png.json`) is no longer listed as its own row or tile; it shows as the `{ }` chip and in the Sidecar rows, which are built from the file's own companion list rather than from cached folder listings. Show Sidecar Files lists companions again, and choosing one, from the tree or a Sidecar row, turns it on; turning it off while a companion is on show shows the file it belongs to. Favourite, Archive, Trash, Delete and Export act on the file and all its companions exactly as before.
- **Operations and notices.** While a file operation runs, a slim strip at the bottom of the reader column shows its progress, "X of Y" and Cancel where it can be cancelled. Toasts sit at the bottom of the reader column.
- **Scrolling.** The tree, grid and rail use scroll views that keep the overlay scroller and set it again when `NSScroller.preferredScrollerStyleDidChangeNotification` fires. WebKit has no per-view style, so Frame sets `AppleShowScrollBars` to `WhenScrolling` in its own volatile argument domain at launch; this covers the document and every other scroll view in Frame's windows, and leaves the system setting untouched.

## Host behavior

Protocol 6 adds `documentStat` for 1–128 root-contained paths. It returns stat fingerprints in one fixed-helper invocation, rejects traversal/symlinks, and omits missing files. No history changes or content transfers occur. Frame renders Markdown/HTML on the Mac, fetching only the page and dependencies through existing authorized file transfers. No remote web server is installed. In the current source Markdown is drawn with the shared `MarkdownRendering` page that RelayBar's preview also uses ([Markdown preview](markdown-preview.md)); Frame adds its palette and lets ordinary images load.

Markdown (`.md`, `.markdown`) and HTML (`.html`, `.htm`) are independent primary files. Media grouping excludes them. Document Archive/Delete acts on the document alone; referenced CSS/JS/data/images are never inferred as companions. Existing JSON/TXT grouping remains unchanged.

The signed app contains a fixed Python helper, executed over the existing SSH control socket. JSON is sent on stdin; paths never enter shell text. Python 3 is required for Frame browsing/actions, Pillow for JPEG/PNG derivatives/metadata, and ffmpeg/ffprobe for video posters/metadata. Nothing is installed automatically.

Listings return precise stat fingerprints and omit symlinks and managed Archive. Previews are 512 or 2048 pixels with bounded metadata and companion text. Frame and RelayBar share filename grouping: longest same-folder dot-prefix wins, exact media filenames take precedence over tied stems, ambiguous stems remain ungrouped. Arbitrary suffixes/extensions and multiple companions are supported, e.g. `name1.png`, `name1.xyz.json`, `name1.qqq.txt`. No content guessing or suffix whitelist.

Conditional validation returns unchanged without another image transfer. Images download for Original/Export; selected video downloads for native AVKit playback, without requiring ffmpeg/ffprobe. Those host tools remain optional for grid posters. No whole-video download occurs just to fill the contact sheet. Each downloaded member is stat-checked before and after SFTP.

Delete immediately unlinks media and all companions. `deleteBatch` accepts up to 500 selected media paths with retained listing IDs and runs one helper invocation with per-item outcomes. Frame limits each batch to 16 distinct listings so expired-listing renewal fits the broker cache; 100 items in one folder still use one mutation request/helper invocation. No move, Trash, delay, confirmation, Undo or recovery record. Files are checked against listing fingerprints before unlinking; partial failures name already-deleted files. Deleting an archived item also removes only its known manifest and empty record directory.

Archive stays separate: the full group moves into managed Archive UUID folders on the same filesystem, retaining original paths. Existing one/two-file records still load. Restore refuses collisions. Moves use no-clobber hard links followed by unlink, preflight and rollback. No recursive source deletion occurs. The old `.FrameTrash` folders, if any, are not automatically modified.

## Bounds

Messages: 8 MiB; derivative: 4 MiB; original/companion download: 100 MiB per file; text preview: 2 MiB input/24,000 characters per companion and 256,000 characters total; listing: 10,000 entries. Four active jobs, 32 retained jobs/listings, eight services and eight transfer directories. Helper CPU/wall limits: 30/50 seconds; Linux address space: 2 GiB. Frame now keeps derivatives/metadata/originals only in bounded session temporary storage. RelayBar's bridge transfer directories remain disposable.
