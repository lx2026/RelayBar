# RelayBar for iPhone and iPad

The thin Xcode target in `Apps/RelayBarMobile` builds RelayBar for iOS and iPadOS 27. The app, its package targets and the off-screen macOS screen gallery use Swift 6 with compiler warnings treated as errors.

## Runtime and storage

Each scene contributes its visible host to one composition runtime. A host realm owns sign-in, its SSH session, file service and readers. Losing a session withdraws its dependent services. Leaving the last visible scene withdraws the realm. Returning reconnects and can show a cached document while the host is unavailable. Host marks distinguish connected, reconnecting, failed and disconnected states. A network path change probes the active SSH session and wakes a pending reconnect. Inbound SSH data extends the path-change probe deadline during transfers. A failed or timed-out probe triggers an immediate reconnect while service pages keep their views and listeners. A failed host retains its reason for Retry on the Hosts screen.

Root registries offer pages, home sections, file actions, location resolvers and PreviewSupport formats. A host inherits the root pages, home sections, file actions and location resolvers and adds its enabled contributions; each host builds its own preview-format registry. Pinned Places supplies pinning for files and folders and retains the original plugin ID. Prompt Search indexes prompts from images opened while enabled and resolves a `prompt:` query in Open Location. On expensive or constrained network paths Data Saver suppresses thumbnails and limits SFTP reads to one negotiated SFTP READ at a time (at most 32 KiB). Paper Appearance selects the house paper palette. Changes to stored plugin choices reconcile the tree. Withdrawing a feature removes its registrations.

The versioned preference document stores host profiles, plugin choices, ordered places, folder order and prompt indexes per host, and up to 100 reading visits with modification stamps and heading-relative positions. The trust document pins each host’s algorithm and fingerprint. Profiles at the same host and port reuse a matching pin. A different pin blocks sign-in and identifies the conflicting profile. Trust and password requests share an ordered queue. Automatic sign-in tries tailnet identity, a device signing key and password. The connection sheet can select password or device-key sign-in for an ordinary SSH server. The first SSH request for a signing key or the Create Key button generates the Secure Enclave key. Settings reads the existing public key. A locked Keychain asks the user to unlock the device and retry. A successfully used password is saved only when requested, as a this-device-only Keychain item.

## Browsing and readers

Hosts accepts a host, an account-qualified endpoint with optional port, or a pasted SSH invocation with an optional `-p` option. A missing account is requested in the connection sheet. Home shows Continue reading, Places, Recent and Websites. Places always starts with Home, followed by the host’s pinned folders and files. Long-press a pin to move or remove it. Legacy favourites migrate in their saved order when preferences load. Turning off Pinned Places hides the pins and their controls. Recent excludes entries already on Home and starts with at most five. Websites lists pinned then other open services.

Folder pages offer a breadcrumb path, grid and list layouts, a per-host sort order and a changed-file filter. Folders precede files. On iPhone, listings with more than fifteen rows show a name filter. Dot entries are counted in a final Show row and remain visible only for the current folder visit. The iPhone reader’s folder path opens the parent. A directory with more than 10,000 entries keeps the partial listing and shows “Showing the first 10,000 items”. Names that are not UTF-8 are left out.

Open Location accepts registered paths, hosts, ports, service addresses, pinned names and indexed prompts. From Home it shows examples and Hosts. From another page it also offers Places, Recent and Websites. Path completion lists the parent directory after a typing pause. Choosing a directory continues completion there. Choosing a file opens it. The app remembers the host’s starting directory for display and looks it up to expand tilde input.

Image captions show the folder and position among its naturally sorted images when the listing is available. By default files sort by modification time, with documents ahead of data files on ties. File tiles distinguish text documents, JSON, HTML, images and video.

Markdown uses the shared parser, Frame reading colours and its enriched-rendering byte limit. A nonpersistent WebKit view disables page JavaScript. Each document has a private URL origin with its actual directory path. The scheme handler serves relative resources with their MIME types, supports parent directories within the host filesystem and restricts requests to the page origin. Navigation stays inside the reader. Scrolling saves the current heading, offset within it and absolute offset. Reopening restores the heading-relative position when available. Text and formatted JSON share the 2 MiB reading limit. Images have a 100 MiB limit. Thumbnails read sources up to 20 MiB and cache only the reduced image. Up to two thumbnail reads and decodes run concurrently. Larger or unknown-size sources use the kind tile. Image details select dimensions, format, bytes, prompt and available generation fields from image metadata and companions.

The cache has a metadata index and separately mapped payload files. Reopening validates remote size and modification time. Replacements write a fresh payload before updating the index. Document and thumbnail payloads share a 256 MiB least-recently-used budget. Keys include profile, account, fingerprint and full path. Settings can clear an individual host. Each operation obtains the current SFTP client from its session, allowing a closed subsystem to be replaced.

File Search adds up to thirty name matches to Open Location. Command-K opens the field on iPad. Search ignores case and accents and requires every typed word in the relative path or a previously read title. Name prefixes come first, followed by word prefixes, substrings and parent-folder matches. A prior visit and then a shorter relative path break ties.

The host realm lists up to four directories at a time, breadth-first per place, yielding to foreground file traffic. Home covers two levels and pinned folders cover twelve. Each place holds up to 20,000 files and 3,000 directories. Hidden entries, dependency and build folders, and directory symlinks are skipped. Browse listings refresh the index. The location sheet shows progress or a limit notice. Atomic checkpoints in the purgeable cache include the pending folders and are isolated by profile, account and pinned key. A completed index is refreshed on connection after fifteen minutes. Data Saver defers the walk until a search. Removing a place or host or disabling File Search clears the corresponding stored indexes.

## iPad and additional readers

At regular iPad width the 264-point sidebar holds Start, Places as a flat list, and Websites. A place is marked while the page shows it or anything inside it; subfolders are reached on the page. The selected page determines the marked row. Opening a document reveals and marks its folder. Start is the default, and a scene returning within ten minutes can restore its previous page. Start and folder pages share the name and location field. Its results replace the page sections while typing. Return opens the top hit. Start shows Continue, pinned then open websites, six recent cards and Places.

Folder pages have lazy cards and a dense list. Date order groups files by day range. Unread Markdown and text previews use up to four concurrent, noninteractive 4 KiB range reads. A preview uses the first level-one heading or front matter title and the first paragraph as plain text. Previews share the purgeable document cache, keyed by host identity, path and file stamp. Data Saver suppresses unread previews. The reader steps through the folder’s displayed order. Back to the folder restores its scroll offset.

The Markdown outline lists all six heading levels. It uses a 288-point rail at 1,000 points of page width, a popover on narrower iPad pages and a bottom panel on iPhone. The reader’s isolated WebKit client reads heading positions to mark the current section and estimate reading time remaining. Focus hides the sidebar and rail. Image details appear below the stage. Open Beside adds a website, hides the sidebar and retains the adjustable divider. Leaving a website captures its tile picture for the purgeable host-identity cache. Removing a host or the last pin and tab for a website evicts its picture. Compact layouts use the phone navigation stack. Media companion files remain available through the owner’s context menu.

HTML files use a separate nonpersistent WebKit store with their own document scheme and no service proxy or token. The scheme resolves local assets inside the document’s resolved folder. A content rule and content security policy restrict network resources by default. The reader can allow or revoke internet resources for the host profile. With permission, the filter still blocks loopback, private IPv4, carrier-grade NAT, link-local, unique-local and site-local IPv6 literals, and the well-known NAT64 prefix `64:ff9b::/96`. It also blocks the profile host, single-label names, and the `.local`, `.internal`, `.lan`, `.home`, `.corp`, `.home.arpa`, `.localhost` and `.ts.net` suffixes. Filtering uses the URL host. A public name resolving to a private address can pass.

HTML Scripts controls page JavaScript independently and starts enabled. The preview opts into WebKit Lockdown Mode, which disables peer connections in the web content process and can limit other web features. A page-world script runs at document start in every frame to hide WebRTC and media capture APIs. The preview denies camera and microphone requests, prevents new windows, and uses `worker-src 'none'` and `webrtc 'block'` in its content security policy. Service pages keep their usual WebKit configuration. The page and iframe checks run on macOS WebKit. Physical iOS verification is pending.

Notebook Preview renders Markdown and fenced code with the shared renderer and displays saved text, PNG and JPEG output. Table Preview renders CSV and TSV with escaped cells, a header row and horizontal scrolling. With Table Preview disabled, opening a CSV or TSV from Files uses the text reader. A recent or restored table preview names the plugin needed to reopen it. Both plugins start enabled and accept UTF-8 files up to 2 MiB. The notebook limit is 2,048 cells and the table limit is 100,000 cells.

Video opens a native player backed by an AVFoundation resource loader. It reads bounded ranges over SFTP, prioritizes the start of each request, cancels superseded requests and offers download and local playback after sustained throughput below the average media bitrate. Share and Save to Files export original bytes. Video downloads submit a continued-processing request with immediate-or-fail scheduling, report progress to the granted task and cancel on expiration. A foreground download without a grant stops on backgrounding. [Apple’s continued-processing request](https://developer.apple.com/documentation/backgroundtasks/bgcontinuedprocessingtaskrequest)

## Demo and verification

Launch with `--demo-host` to use an isolated sample profile and bundled in-memory workspace. The demo supplies the same connection and file protocols as SSH. It includes Markdown, posters with generation metadata, text, JSON, a scripted HTML report with a reference poster served in process at a stand-in internet address, a notebook, CSV and a three-second MP4. The demo preview sends requests for `reference.invalid` through a loopback proxy with failover disabled. Its in-process HTTP streams serve a dashboard on port 6006 and a notebook on port 8888 that requires an exact localhost Host header. Both use the app’s proxy and gate.

From the repository root run `./scripts/test.sh mobile` for the macOS tests, including the loopback OpenSSH fixture. Run `swift run --package-path Apps/RelayBarMobile ScreenGallery .build/screens` to write 390 × 844 PNGs in both appearances. ImageRenderer draws the shared SwiftUI content off screen. Document and Resume use snapshots of the rendered Markdown from a WebKit view in a hidden window. Additional portraits cover the table and code block, display equation, and Home, Folder, Browser, Offer, Tabs and Go at the smallest and largest Dynamic Type sizes. Browser captures the demo dashboard through the proxy. Display headings and the location capsule cap their type scale while rows and body text can grow. Live interaction and accessibility checks are tracked in the [device checklist](../../verification/079-mobile-app-device.md).

The light and dark gallery includes 1376 × 1032 iPad captures of Start, Find, folder cards and list, the reader rail and outline popover, an image folder, image details and a split website. Phone captures include hidden items, the outline panel, path completion, HTML, notebook and table readers. Physical playback, AirPlay, sharing and continued processing are tracked in the [mobile device checklist](../../verification/mobile-device-checklist.md).

## Settings and plugins

Open Settings from the Hosts gear or from the current host. It shows Plugins, per-host cache usage and Clear, the device’s copyable SSH public key, and the app version and build. The phone uses the shared Plugins list and detail. A wide Settings panel shows the iPad list, map and inspector. The list names saved hosts whose override differs from the global switch, including offline hosts. The iPad map highlights selected connections in the accent colour, and its inspector identifies host features by host name. The detail includes saved hosts even when they have no live realm.

Notebook Preview, Table Preview, HTML Scripts, Pinned Websites, Pinned Places, File Search, Prompt Search, Localhost Compatibility, Data Saver and Paper Appearance default on. Log Follow, Delete with Undo, The Host’s Network and Service Labels default off. The preference document stores choices by plugin ID and host overrides by profile UUID and plugin ID. Inherit removes the override. A host can independently select its reader formats, script permission and paper colours. Restored plugin pages, service tabs and reading history retain their saved locations and name the required plugin when disabled.

Delete is available in a file’s context menu when its listing supplies a regular-file fingerprint. The confirmation names the full path. Undo cancels a five-second delay before submission; so does the scene becoming inactive or the view leaving the screen. At submission the app checks the action’s lifetime and uses the listing’s fingerprint with SFTP remove. A changed target or a lost connection reports an error. No delete is replayed on reconnect.

Follow log opens a text file at its last 64 KiB. Polls use the SFTP cursor and carry its identity through successive reads. Truncation or a changed anchor clears the old text and restarts at the tail. Scrolling up pauses follow. Resume follows the end again.

The phone gallery includes Settings, Plugins, plugin detail, delete confirmation and Undo, Log Follow, and both service approval sheets. The iPad gallery includes the Plugins workspace. The demo host has a growing training log and supports in-memory deletion. Settings in demo mode also offers examples of both approval sheets.
